# Higher [[Inductive-Types|Inductive Types]]

## 1. The problem: free generation, but with equalities

Ordinary inductive types (Chapter 5) are *freely generated by their constructors*: $\mathbb{N}$ is "nothing but" $0$ and iterated $\mathsf{succ}$, and there are no extra equalities except the ones forced by the rules of identity types. That is exactly what makes a recursion principle easy to state: to map out of $\mathbb{N}$, say where $0$ and $\mathsf{succ}$ go.

Now suppose you want a type with some *built-in identifications*. Three examples that the book works through:

- a type with one point and one non-trivial loop on it (the circle),
- a type that is "$A$ with all its elements declared equal" (propositional truncation),
- a type that is "$A$ modulo a relation $R$" (quotient).

In ordinary type theory you cannot add such a type. You cannot simply postulate $q(a)=q(b)$ for related $a,b$, because the type would then not have a recursion principle that takes the new equalities into account. The book's solution is to extend the notion of constructor so that a constructor may output not only *points* of the type but also *paths* (and paths between paths, …) in it. These are **higher inductive types** (HITs).

The motivation is homotopical (§6.1): if a type is a higher groupoid, a "generating set" should be allowed in every dimension, just as a space can be built from points, then 1-cells, then 2-cells.

## 2. The definition by example: the circle $\mathbb{S}^1$

$\mathbb{S}^1$ is generated by

- a point constructor $\mathsf{base} : \mathbb{S}^1$,
- a path constructor $\mathsf{loop} : \mathsf{base} =_{\mathbb{S}^1} \mathsf{base}$.

Compare with $\mathbf{2}$ (generated by two points $0_{\mathbf{2}}, 1_{\mathbf{2}}$) and $\mathbb{N}$ (generated by $0$ and $\mathsf{succ}$): the pattern is the same, only the constructor types are more general. A path constructor must declare its **source** and **target** (here both $\mathsf{base}$).

Four caveats from §6.1 that are easy to get wrong:

1. **"Generation" is real generation.** Besides $\mathsf{loop}$, the type contains $\mathsf{loop}\cdot\mathsf{loop}$, $\mathsf{loop}^{-1}$, $\mathsf{refl}_{\mathsf{base}}$ and so on, and they are all different. This is a departure from ordinary inductive types, where "nothing is in the type but what the constructors put in".
2. **It is free generation, not presentation.** You cannot impose an axiom such as $\mathsf{loop}\cdot\mathsf{loop}=\mathsf{refl}$. But you can add a new 2-dimensional constructor stating it, and then the new constructor is itself free. In $\infty$-groupoids "presentation" and "free generation" are interchangeable this way.
3. **Only the type itself gets an induction principle**, not its identity types. Identity types of a HIT keep ordinary path induction, so computing them (for example, are there paths $\mathsf{base}=\mathsf{base}$ other than powers of $\mathsf{loop}$?) is non-trivial. That is what Chapter 8 is about.
4. **Constructor dimension is not the same as homotopy dimension.** $\mathbb{S}^2$ has only a 2-dimensional constructor $\mathsf{surf}$, yet has non-trivial 3-dimensional paths (the book notes this is the Hopf fibration showing up).

## 3. Recursion and induction: dependent paths

### 3.1 Recursion principle (non-dependent)

First-principles reading: *a map out of a freely generated object is determined by where the generators go.* For $\mathbb{S}^1$: given a type $B$ with a point $b : B$ and a loop $\ell : b = b$, there is $f : \mathbb{S}^1 \to B$ with

$$f(\mathsf{base}) \equiv b, \qquad \mathsf{ap}_f(\mathsf{loop}) = \ell .$$

Note the two computation rules have different status (§6.2):

- point constructors compute **judgmentally** ($\equiv$),
- path constructors compute only **propositionally** ($=$). The book gives the reasons: $\mathsf{ap}_f$ is a *defined* operation (via path induction), not a primitive of the type theory, so it should not appear inside a judgmental equality; and semantic and implementation considerations (Notes).

The book therefore uses a hybrid notation: $f(\mathsf{base}) :\equiv b$ but $f(\mathsf{loop}) := \ell$ (meaning $\mathsf{ap}_f(\mathsf{loop}) = \ell$). It also remarks (footnote 1) that HITs are thus a mix of *rules* and *axioms*, and hopes for a future theory presenting them with rules only.

### 3.2 Induction principle (dependent): why dependent paths are needed

To prove $\prod_{x:\mathbb{S}^1} P(x)$ we must give

- $b : P(\mathsf{base})$, and
- "a path from $b$ to $b$ lying over $\mathsf{loop}$".

Why not just a path $b = b$? Because $b$ lives in the *fiber* $P(\mathsf{base})$; the loop moves around the *base* $\mathbb{S}^1$, and the fiber can be twisted as you go around. The book's answer (from §2.3) is to **transport**: a dependent path from $u:P(x)$ to $v:P(y)$ over $p:x=y$ is

$$(u =^P_p v) :\equiv (\mathsf{transport}^P(p,u) = v). \tag{6.2.2}$$

So the induction principle says: given $P:\mathbb{S}^1\to\mathcal{U}$, $b:P(\mathsf{base})$ and $\ell : b =^P_{\mathsf{loop}} b$, there is $f:\prod_{x:\mathbb{S}^1}P(x)$ with $f(\mathsf{base})\equiv b$ and $\mathsf{apd}_f(\mathsf{loop})=\ell$.

Note that you only specify the path over the *constructor* $\mathsf{loop}$, not over $\mathsf{loop}\cdot\mathsf{loop}$ etc.: that is precisely the content of "freely generated". Remark 6.2.3 notes that other definitions of dependent paths (e.g. $u = (p^{-1})_*(v)$, heterogeneous equality) give equivalent types, and $p_*(u)=v$ is chosen because it makes $\mathsf{apd}$ and the transport lemmas of §2.5 easiest to use.

Informally, applying the induction principle is a case split into "when $x$ is $\mathsf{base}$" and "when $x$ varies along $\mathsf{loop}$" (Remark 6.2.4); the latter phrase has no formal meaning beyond marking that proof obligation.

### 3.3 Deriving recursion from induction, and the universal property

Lemma 6.2.5 gets the non-dependent recursor from the dependent one by taking the constant family $P \equiv \lambda x.A$. The subtle part (the book calls it "surprisingly a little tricky") is converting $\mathsf{apd}_f(\mathsf{loop})$ into $\mathsf{ap}_f(\mathsf{loop})$, which uses $\mathsf{transportconst}$ and Lemma 2.3.8:

$$\mathsf{apd}_f(\mathsf{loop}) = \mathsf{transportconst}^A_{\mathsf{loop}}(f(\mathsf{base}))\cdot \mathsf{ap}_f(\mathsf{loop}).$$

Lemma 6.2.8 is the uniqueness principle: two maps $f,g:\mathbb{S}^1\to A$ agreeing on $\mathsf{base}$ ($p$) and on $\mathsf{loop}$ (via a square $q$) are equal pointwise. Together they give the **universal property of the circle** (Lemma 6.2.9):

$$(\mathbb{S}^1 \to A) \;\simeq\; \sum_{x:A} (x = x).$$

That is the HIT analogue of "a function out of an inductive type is determined by its constructor data", and the book says the same shape of lemma holds for other HITs.

## 4. A tour of the HITs in the chapter

### 4.1 The interval $I$ (§6.3)

Generated by $0_I, 1_I : I$ and $\mathsf{seg} : 0_I =_I 1_I$. Up to homotopy it is boring: **it is contractible** (Lemma 6.3.1). But it is useful type-theoretically: it gives a **proof of function extensionality** (Lemma 6.3.2). From $p:\prod_x f(x)=g(x)$ define $\widetilde{p}_x : I\to B$ by $0_I\mapsto f(x)$, $1_I\mapsto g(x)$, $\mathsf{seg}\mapsto p(x)$, then $q(i):\equiv\lambda x.\widetilde p_x(i)$ and $\mathsf{ap}_q(\mathsf{seg}) : f=g$. (Exercise 6.10 asks for the remaining step to get the full axiom.)

### 4.2 Circles and spheres (§6.4–6.5)

- **$\mathbb{S}^1$ is non-trivial**: $\mathsf{loop}\neq\mathsf{refl}_{\mathsf{base}}$ (Lemma 6.4.1). Otherwise every type $A$ with $p:x=x$ would have $p=\mathsf{refl}_x$ by the recursor, making every type a set, contradicting Example 3.1.9.
- Lemma 6.4.2 builds an element of $\prod_{x:\mathbb{S}^1}(x=x)$ not equal to $x\mapsto\mathsf{refl}_x$; this uses $\mathsf{transport}^{x\mapsto(x=x)}(p,q)=p^{-1}\cdot q\cdot p$.
- Corollary 6.4.3: any universe containing $\mathbb{S}^1$ is not a 1-type (via univalence and function extensionality).
- **$\mathbb{S}^2$**: point $\mathsf{base}$ and a 2-path $\mathsf{surf}:\mathsf{refl}_{\mathsf{base}}=\mathsf{refl}_{\mathsf{base}}$. Its recursion principle uses $\mathsf{ap2}_f$ (Lemma 6.4.4); its induction principle requires dependent 2-paths, $\mathsf{transport}^2$ and $\mathsf{apd2}_f$ (Lemmas 6.4.5–6.4.6). The book explicitly says this "gets more and more complicated as we go up in dimension".
- **$\mathbb{S}^n$ directly**: a point and an $n$-loop $\mathsf{loop}_n:\Omega^n(\mathbb{S}^n,\mathsf{base})$ (writing the induction principle needs dependent $n$-loops; Exercise 6.4).

### 4.3 Suspension (§6.5)

$\Sigma A$ is generated by $N,S:\Sigma A$ and $\mathsf{merid}:A\to(N=_{\Sigma A}S)$. It is "the universal way of making the points of $A$ into paths". Highlights:

- $\Sigma\mathbf{2}\simeq\mathbb{S}^1$ (Lemma 6.5.1, proved with explicit quasi-inverses $f,g$).
- This yields an *inductive* definition of all spheres: $\mathbb{S}^0:\equiv\mathbf{2}$, $\mathbb{S}^{n+1}:\equiv\Sigma\mathbb{S}^n$, with $\mathbb{S}^{-1}:\equiv\mathbf{0}$.
- Universal property (Lemma 6.5.4): $\mathrm{Map}_*(\Sigma A,B)\simeq\mathrm{Map}_*(A,\Omega B)$, so $\mathrm{Map}_*(\mathbb{S}^n,B)\simeq\Omega^nB$ (the suspension–loop adjunction).

### 4.4 Cell complexes and hubs-and-spokes (§6.6–6.7)

A finite CW complex becomes a HIT by turning $n$-cells into $n$-path constructors. The torus $T^2$: point $b$, paths $p,q:b=b$, and a 2-path $t:p\cdot q=q\cdot p$. Writing its induction principle is "the trickiest so far" (Exercise 6.1) because $\mathsf{apd}$ only preserves concatenation up to homotopy.

**Hubs and spokes** is the trick that avoids this: replace an $n$-dimensional path constructor by a *hub point* $h$ and, for each $x$ in the boundary sphere, a 1-path (spoke) $s(x):f(x)=h$. For the torus: $h:T^2$ and $s:\prod_{x:\mathbb{S}^1}f(x)=h$ with $f(\mathsf{loop}):= p\cdot q\cdot p^{-1}\cdot q^{-1}$. Only point and 1-path constructors remain, so no dependent 2-paths are needed. Remark 6.7.1 explains why a separate hub is required: without it the cone is twisted back onto a boundary point, unless a further 2-path is added. Remark 6.7.2: judgmental computation rules are not preserved by this translation, propositional ones are.

### 4.5 Pushouts (§6.8)

For a span $A\xleftarrow{f}C\xrightarrow{g}B$, the pushout $A\sqcup_C B$ has $\mathsf{inl},\mathsf{inr}$ and $\mathsf{glue}:\prod_{c:C}\mathsf{inl}(f(c))=\mathsf{inr}(g(c))$. Its universal property (Lemma 6.8.2) is

$$(A\sqcup_C B\to E)\;\simeq\;\mathsf{cocone}_{\mathcal{D}}(E),\qquad \mathsf{cocone}_{\mathcal D}(E):\equiv\sum_{i:A\to E}\sum_{j:B\to E}\prod_{c:C}\big(i(f(c))=j(g(c))\big).$$

The book lists standard constructions as pushouts: suspension ($\mathbf 1\leftarrow A\to\mathbf 1$), the join $A*B$, the cone/cofiber, the wedge $A\vee B$ and the smash product $A\wedge B$. Remark 6.8.4: colimits do not preserve truncatedness ($\mathbf 1\leftarrow\mathbb{S}^0\to\mathbf 1$ has pushout $\mathbb{S}^1$, not a set), motivating §6.9.

### 4.6 Truncations (§6.9)

Propositional truncation $\|A\|$ is the HIT with $|{-}|:A\to\|A\|$ and, for all $x,y:\|A\|$, a path $x=y$. That second constructor *is* "$\|A\|$ is a mere proposition". This is the first genuinely recursive HIT (the second constructor takes inputs of the type being defined). The recursion principle has exactly the hypothesis of §3.7 ($B$ a mere proposition); the induction principle is nearly useless since maps between mere propositions are unique.

The 0-truncation $\|A\|_0$ adds, for $x,y$ and $p,q:x=y$, a path $p=q$. Lemma 6.9.1 gives an induction principle for families of sets; Lemma 6.9.2 the universal property $(\|A\|_0\to B)\simeq(A\to B)$ for sets $B$; Lemma 6.9.3 set-pushouts. Two caveats: constructors whose *inputs* mention paths of the type being defined are awkward (one can reroute via an auxiliary type $S$ with two points and two parallel paths, which is equivalent to $\mathbb{S}^1$), and the scheme does not generalise to $n$-truncation uniformly. The book therefore defers the general $n$-truncation to §7.3.

### 4.7 Set-quotients (§6.10)

For $R:A\times A\to\mathsf{Prop}$, the set-quotient $A/R$ has $q:A\to A/R$, for $R(a,b)$ a path $q(a)=q(b)$, and the 0-truncation constructor. Results:

- $q$ is surjective (Lemma 6.10.2).
- Universal property (Lemma 6.10.3): for every set $B$,
$$(A/R\to B)\;\simeq\;\sum_{f:A\to B}\ \prod_{a,b:A}\big(R(a,b)\to f(a)=f(b)\big).$$
- For an equivalence relation, $R(a,b)\simeq(q(a)=q(b))$, and the quotient agrees with the impredicative "set of equivalence classes" $A/\!/R$ (Theorem 6.10.6; this uses univalence and function extensionality, and raises the universe level unless resizing is assumed).
- **Canonical representatives** (Lemma 6.10.8): if an idempotent $r:A\to A$ satisfies $(r(x)=r(y))\simeq(x\sim y)$, the quotient is the type of fixed points $\sum_{x:A}(r(x)=x)$. Example: $\mathbb{Z}:\equiv(\mathbb N\times\mathbb N)/\!\sim$ with $(a,b)\sim(c,d):\equiv(a+d=b+c)$ and $r$ normalising to $(k,0)$ or $(0,m)$. This yields an induction principle for $\mathbb{Z}$ (Lemma 6.10.12) and powers $p^n$ of loops for $n:\mathbb{Z}$ (Corollary 6.10.13).

### 4.8 Algebra (§6.11)

The free monoid on a set is just $\mathsf{List}(A)$, because words have computable canonical forms. Free *groups* lack decidable normal forms in general, but a HIT $F(A)$ gets them for free: constructors $\eta,m,e,i$, path constructors for associativity, unit and inverse laws, and the 0-truncation constructor. Theorem 6.11.6 says it is the free group; this proves existence of free groups by *stating the universal property*, with no explicit construction. Theorem 6.11.7 gives the concrete model: the set-quotient of $\mathsf{List}(A+A)$ by cancellation of adjacent $a,\hat a$. With decidable equality on $A$ this is the fixed-point quotient of a word-reduction idempotent. Further constructions: amalgamated free products $H*_G K$, group presentations as coequalisers, and $\pi_n(A,a):\equiv\|\Omega^n(A,a)\|_0$. The scope is limited to (infinitary) algebraic theories, not to ones with partial operations like fields.

### 4.9 The flattening lemma (§6.12)

HITs + univalence interact through *type families defined by recursion on a HIT*. Example: given $e:X\simeq X$, define $P:\mathbb{S}^1\to\mathcal U$ by $P(\mathsf{base}):\equiv X$, $P(\mathsf{loop}):=\mathsf{ua}(e)$; then $\mathsf{transport}^P(\mathsf{loop},u)=e(u)$ (Lemma 6.12.1).

The **flattening lemma** (Lemma 6.12.2): for $W$ the coequaliser HIT generated by $c:A\to W$ and $p:\prod_{b:B}c(f(b))=c(g(b))$, with $C:A\to\mathcal U$, $D:\prod_{b}C(f(b))\simeq C(g(b))$ and $P(c(a)):\equiv C(a)$, $P(p(b)):=\mathsf{ua}(D(b))$:

$$\Big(\sum_{x:W}P(x)\Big)\;\simeq\;\widetilde W,$$

where $\widetilde W$ has constructors $\widetilde c:\prod_a C(a)\to\widetilde W$ and $\widetilde p:\prod_b\prod_{y:C(f(b))}\widetilde c(f(b),y)=\widetilde c(g(b),D(b)(y))$. The proof builds maps both ways using the recursion/induction principles and a lemma (6.12.7) whose complicated statement exists only to make the path equation well-typed. The book flags this as a good example of "proof-relevant mathematics", and the main tool Chapter 8 uses for computing homotopy groups.

## 5. What counts as a legal HIT? (§6.13)

No general definition is given; this is stated as active research. The informal discipline is:

- Constructors are (dependent) functions with the usual **strict positivity** requirement on inputs.
- The only new freedom is that a constructor's *output* may be an iterated identity type $u=_W v$, $p=_{(u=_Wv)}q$, …, where $u,v,\ldots$ can mention **earlier** constructors. Constructor order therefore matters (for ordinary inductive types it does not).
- Source and target expressions must be "natural": only use operations preserved by all functions between types (e.g. path concatenation is fine). Example 6.13.1 shows the failure mode: with a non-natural $f:\prod_{X:\mathcal U}X\to X$, a constructor $\sigma:f_K(a)=f_K(b)$ would have no sensible induction principle.
- This also excludes the first presentation of $\|A\|_0$ (inputs mention paths in $W$), which §7.3 replaces by a legal construction.

## 6. Grounding in code

HITs are the part of HoTT that **mainstream languages cannot express**, and the exercise is instructive about *why*.

### 6.1 Rust: what survives is the universal property

Rust has no identity types, so the path constructor cannot be a value of the type. What you *can* model is the **recursor as the interface** and use a canonical form for the quotient. The universal property $(\mathbb{S}^1\to A)\simeq\sum_{x:A}(x=x)$ says a "map out of the circle" is a point plus a loop. In a setting with only sets this loop is a unit, so the best we can do is the *data*:

```rust
/// Data of a map S^1 -> A, per Lemma 6.2.9: a point plus a loop at it.
/// In Rust the loop `base == base` can only be a witness we choose to carry.
struct CircleMap<A, Loop> {
    base: A,
    loop_: Loop, // stands for a path `base = base`; no Rust type can enforce this
}
```

Set-quotients are the part that transfers directly. The universal property says a function out of $A/R$ is a function out of $A$ that respects $R$. In Rust that obligation is *unchecked*, and the usual implementation is a canonical-form idempotent in the sense of Lemma 6.10.8:

```rust
/// Z := (N x N) / ~ with (a,b) ~ (c,d) iff a + d == b + c.
/// `normalize` is the idempotent r of Lemma 6.10.8; the quotient is its fixed points.
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
struct Int(u64, u64); // invariant: Int(k, 0) or Int(0, m)

fn normalize(a: u64, b: u64) -> Int {
    if a >= b { Int(a - b, 0) } else { Int(0, b - a) }
}
impl std::ops::Add for Int {
    type Output = Int;
    fn add(self, o: Int) -> Int { normalize(self.0 + o.0, self.1 + o.1) } // respects ~
}
```

The book's point is that the quotient HIT lets you *skip* writing `normalize` when no computable canonical form exists (free groups with undecidable word problem), and still reason with the universal property. Rust must pick a normal form or a union-find-style representative, and the "respects $R$" proof is on you.

### 6.2 Python: the free group as a quotient of words

```python
# F'(A): set-quotient of List(A + A) by cancelling adjacent (a, a-hat).
# Letters are (name, +1) or (name, -1). Reduction is the idempotent r of Lemma 6.10.8;
# it exists because A has decidable equality.
def reduce(word):
    out = []
    for g, s in word:
        if out and out[-1] == (g, -s):
            out.pop()
        else:
            out.append((g, s))
    return tuple(out)

def mul(x, y):          # descends to the quotient
    return reduce(x + y)

def inv(x):             # reverse and flip, as in the proof of Theorem 6.11.7
    return tuple((g, -s) for g, s in reversed(x))

assert mul(inv((("a", 1), ("b", 1))), (("a", 1), ("b", 1))) == ()
```

For a type with *undecidable* equality, this `reduce` has no analogue; that is the case where the HIT $F(A)$ earns its keep.

### 6.3 Lean: quotients yes, higher paths no

Lean 4 has the set-quotient built into its kernel, which is exactly §6.10's $A/R$ restricted to propositional $R$ and to sets:

```lean
-- Quot r : q a = q b whenever r a b, plus recursion into functions respecting r
#check @Quot.mk      -- (r : α → α → Prop) → α → Quot r
#check @Quot.sound   -- r a b → Quot.mk r a = Quot.mk r b
#check @Quot.lift    -- (f : α → β) → (∀ a b, r a b → f a = f b) → Quot r → β
```

`Quot.lift` is the recursion principle of Lemma 6.10.3: the second argument is the "respects $R$" hypothesis. Lean also derives function extensionality from `Quot`, in the spirit of the book's remark (Notes) that quotient types in intensional type theory imply funext [Hof95].

What Lean *cannot* do is the general HIT. Its `Eq` lives in `Prop`, so it is proof-irrelevant: all paths between two points are equal, which collapses $\mathbb{S}^1$ (where $\mathsf{loop}\neq\mathsf{refl}$) to a point-like type. HITs with non-trivial higher structure are implemented in cubical systems (e.g. Cubical Agda) or via the Licata "private data types" trick the book mentions in the Notes, which gives judgmental rules for points but only propositional rules for paths. So the **"propositional computation rule for path constructors"** of §6.2 is not a theoretical quirk but the observed behaviour of the available implementations.

## 8. Relevance to the compiler and elaborator project

Focus-area tag: **Type Theory** (`type-theory`). The workbench notes mark this topic as *not* directly load-bearing for the refinement-type compiler, so only the connections below are worth keeping; the rest is background.

- **Inductive types** (`type-theory`): a HIT is an inductive type whose constructor *outputs* are widened to identity types. The elaborator machinery for ordinary inductives (positivity checking, generating the recursor and its computation rules) is exactly what must be extended, and §6.13's ordering and naturality conditions are what a checker for HIT declarations would have to enforce. This is a **load-bearing observation for the kernel only if you ever target HoTT**; for a refinement-type language it is optional.
- **Definitional equality** (`type-theory`): the choice of *judgmental for points, propositional for paths* (§6.2) is a concrete design decision about what `isDefEq` must decide. Keeping path-constructor computation propositional means the kernel's defeq stays free of $\mathsf{ap}$/$\mathsf{apd}$ reduction rules, and this is the same reason Lean's kernel treats `Quot.lift` computation on `Quot.mk` as a defeq (iota-like) rule while `Quot.sound` is an axiom.
- **Quotients as a practical feature**: Lemma 6.10.3 is the template for a kernel-supported quotient type: introduction $q$, eliminator that demands a respect-$R$ proof. Lean's `Quot` is the closest existing model, and the proof obligation "$f$ respects $R$" is an ordinary verification condition. That makes quotients the one HIT-derived feature with a realistic path into a refinement-type language (e.g. refinement over canonical representatives, Lemma 6.10.8).
- **Mere propositions and truncation** (`type-theory`): $\|A\|$ is the type-theoretic version of proof irrelevance / "there exists" without a witness, the same role Lean's `Prop` plays. Not forcing a connection beyond this to unification or Hoare logic: the chapter does not support one.
