# Identity Types and Equality

## 1. The problem: two kinds of "equal"

A type checker has to decide when two terms are the *same*. A proof assistant also has to let you *prove* two terms are the same. These are different jobs.

- **Judgmental equality** $a \equiv b : A$. This is a *judgment* of the meta-theory, like $a : A$. It is checked by the machine, by computation (the $\beta$-, $\eta$- and recursor rules). It is not a type, so you cannot quantify over it or assume it as a hypothesis inside the theory. The book calls it "purely definitional".
- **Propositional equality** $a =_A b$. This is a *type*. By propositions-as-types, a proof of "$a$ equals $b$" must be a term, so the statement must be a type. Since the statement depends on $a$ and $b$, it is a type family
$$\mathsf{Id}_A : A \to A \to \mathcal{U}, \qquad (a =_A b) :\equiv \mathsf{Id}_A(a,b).$$

The book's example of the gap (Remark 1.12.2): associativity of $+$ on $\mathbb{N}$ is a propositional equality, not a judgmental one. Even $n + 1 = 1 + n$ is not judgmental for a *generic* $n$, though $3 + 1 \equiv 1 + 3$ holds, since both sides compute to $4$. Facts about a generic $n$ can only be reached by $\mathbb{N}$-induction, whose output must be a type. So they must be stated with $=$.

The book's point is that **propositional equality is "the equality of mathematics"** in HoTT. Judgmental equality is a feature of the rule system.

The idea that sets up everything else: nothing forces $a = b$ to be a mere "yes/no" fact. Elements of $a = b$ are *identifications*, and there may be many distinct ones. In the homotopy reading they are paths from $a$ to $b$ in the space $A$.

## 2. The rules (§1.12)

Like every other type former in Chapter 1, $=_A$ has formation, introduction, elimination and computation rules.

| Rule | Content |
|---|---|
| Formation | $A : \mathcal{U}$, $a, b : A$ gives $(a =_A b) : \mathcal{U}$ |
| Introduction | $\mathsf{refl} : \prod_{a:A} (a =_A a)$ |
| Elimination | path induction $J$ (below) |
| Computation | $\mathsf{ind}_{=_A}(C, c, x, x, \mathsf{refl}_x) :\equiv c(x)$ |

A consequence of introduction: if $a \equiv b$ then $\mathsf{refl}_a : a =_A b$ is well typed. This works because $a \equiv b$ makes the types $a =_A b$ and $a =_A a$ judgmentally equal. So **judgmental equality implies propositional equality**, but not conversely.

### 2.1 Indiscernibility of identicals (the "recursion" form)

For every family $C : A \to \mathcal{U}$ there is a function
$$f : \prod_{x,y:A}\prod_{p : x =_A y} C(x) \to C(y), \qquad f(x,x,\mathsf{refl}_x) :\equiv \mathsf{id}_{C(x)}.$$
This is "equals may be substituted for equals". It is the recursion principle for $=$, and it only uses the *existence* of $p$. Chapter 2 renames it **transport** ($p_*$).

### 2.2 Path induction (the "induction" form, $J$)

Given $C : \prod_{x,y:A}(x =_A y) \to \mathcal{U}$ and $c : \prod_{x:A} C(x,x,\mathsf{refl}_x)$, there is
$$f : \prod_{x,y:A}\prod_{p : x =_A y} C(x,y,p), \qquad f(x,x,\mathsf{refl}_x) :\equiv c(x).$$

Packaged as one term (traditionally called $J$):
$$\mathsf{ind}_{=_A} : \prod_{C}\Big(\prod_{x:A} C(x,x,\mathsf{refl}_x)\Big) \to \prod_{x,y:A}\prod_{p:x=_A y} C(x,y,p).$$

**Based path induction** fixes the left endpoint $a$. Given $C : \prod_{x:A}(a =_A x) \to \mathcal{U}$ and $c : C(a, \mathsf{refl}_a)$, we get $f : \prod_{x:A}\prod_{p:a=x} C(x,p)$ with $f(a,\mathsf{refl}_a) :\equiv c$.

The book proves the two are equivalent. The easy direction instantiates the free $x$ of $J$. The hard direction builds one instance of $J$ that covers all instances of the based rule at once. It uses
$$D(x,y,p) :\equiv \prod_{C : \prod_{z:A}(x = z)\to\mathcal{U}} C(x,\mathsf{refl}_x) \to C(y,p).$$
This uses a *universe*: if $C$ lands in $\mathcal{U}_i$, then $D$ lands in $\mathcal{U}_{i+1}$. The book notes this can be avoided (Exercise 1.7).

### 2.3 Why "every path is refl" is *not* the reading

The confusing point is that $J$ looks like the induction principle for $\mathbb{N}$ or $A+B$, which says "every element is built from constructors". Applied naively, "every path is $\mathsf{refl}$" would contradict the homotopy reading, where a space can have many non-trivial paths.

The book's resolution (Remark 1.12.1): **the *family* of identity types is inductively defined, not each individual identity type.**

- Path induction says the triple-space $\sum_{x,y:A}(x = y)$, the *free path space* with both endpoints free, is generated by the constant loops $(x,x,\mathsf{refl}_x)$. One can prove $(x,y,p) = (x,x,\mathsf{refl}_x)$ in $\sum_{x,y}(x=y)$ by path induction on $p$.
- Likewise, for fixed $a$, $\sum_{y:A}(a = y)$ (the "based path space", read as the singleton subset $\{a\}$) is contractible. $(y,p) = (a,\mathsf{refl}_a)$ by based path induction.
- What you **cannot** do is apply induction to a family $C(p)$ with *both* endpoints fixed, e.g. $C : (a = a) \to \mathcal{U}$. You cannot prove that every loop $p : x = x$ equals $\mathsf{refl}_x$.

The topological picture is a rope around a pole. With both ends held fixed, a loop around the hole cannot be contracted. If one endpoint is allowed to move, it contracts. Fixed endpoints versus free endpoints is exactly the difference between $x = x$ and $\sum_y (x = y)$.

### 2.4 Disequality

$x \neq_A y :\equiv \neg(x =_A y)$. You cannot prove $x = y$ by refuting $x \neq y$. That would be double-negation elimination, which is not available constructively (§3.4).

## 3. Identity types as an inductive family (§5.8)

Section 5.8 re-reads path induction as the induction principle of an **inductive family with indices** (§5.7). There are two presentations:

1. Parameter $A$, indices $a, b : A$, one constructor $\mathsf{refl}_a : a =_A a$. The extracted induction principle is $J$.
2. Parameters $A$ and $a_0 : A$, one index $b : A$, constructor $\mathsf{refl}_{a_0} : a_0 =_A a_0$. The extracted principle is based path induction.

The book explains why this caused historical confusion: for $\mathbf{2}$ and $\mathbb{N}$, every element really is a constructor application, but here there is one constructor and many paths. The explanation is that [[Inductive-Types|inductive types]] are **freely generated** by their constructors, and a free structure contains the generators *and the results of the ambient operations*. For a group those operations are multiplication and inverse. For a type viewed as an $\infty$-groupoid there are no operations on *elements*, but there are operations on *paths* (concatenation, inversion). Only a type *family* $B : A \to \mathcal{U}$ (a functor) acts on paths.

> $(a_0 =_A -)$ is the **functor $A \to \mathcal{U}$ freely generated by one element $\mathsf{refl}_{a_0} : F(a_0)$**. By the Yoneda lemma that is the representable functor $\hom_A(a_0, -)$. Identity types are hom-spaces of paths.

The book also notes that only an extra principle such as univalence can exhibit a loop that is not $\mathsf{refl}$. The example is a non-trivial path $\mathbf{2} =_{\mathcal{U}} \mathbf{2}$ (Example 3.1.9).

### 3.1 Identity systems: characterizing $=$ by its induction principle

Because $=_A$ is inductive, any other family with the same induction principle is equivalent to it.

**Definition 5.8.1.** A *pointed predicate* is $(R, r_0)$ with $R : A \to \mathcal{U}$ and $r_0 : R(a_0)$. It is an **identity system at $a_0$** if for every $D : \prod_{b:A} R(b)\to\mathcal{U}$ and $d : D(a_0,r_0)$ there is $f : \prod_{b}\prod_{r:R(b)} D(b,r)$ with $f(a_0,r_0) = d$.

**Theorem 5.8.2.** The following are logically equivalent:
1. $(R, r_0)$ is an identity system at $a_0$;
2. for every pointed predicate $(S, s_0)$, the type of pointed maps $\mathsf{ppmap}(R,S)$ is contractible;
3. for every $b$, $\mathsf{transport}^R(-, r_0) : (a_0 = b) \to R(b)$ is an equivalence;
4. $\sum_{b:A} R(b)$ is contractible.

Theorem 5.8.4 is the two-variable version, for $R : A \to A \to \mathcal{U}$ with $r_0 : \prod_a R(a,a)$. The same conditions hold with "for all $a$" (for example: $\sum_b R(a,b)$ is contractible).

**Why it matters.** Univalence says exactly that $(- \simeq -)$ with identities $\mathsf{id}_A$ satisfies condition (iv). It is therefore equivalent to **equivalence induction** (Corollary 5.8.5): to prove something about all equivalences $e : A \simeq B$, it suffices to treat $\mathsf{id}_A : A \simeq A$. Function extensionality is the same statement for $(-\sim-)$ on dependent functions. This is the mechanism behind many proofs in the book.

## 4. Paths between paths (§2.11)

There is no closed-form description of $p =_{a=a'} q$ in general. The book gives instead:

- **Theorem 2.11.1.** If $f : A \to B$ is an equivalence, then $\mathsf{ap}_f : (a =_A a') \to (f(a) =_B f(a'))$ is an equivalence. The inverse is built from $\mathsf{ap}_{f^{-1}}$ conjugated by the homotopy $\beta : f^{-1}\circ f \sim \mathsf{id}$, as $\beta_a^{-1} \cdot \mathsf{ap}_{f^{-1}}(-) \cdot \beta_{a'}$. The proof uses functoriality of $\mathsf{ap}$ and naturality of homotopies.
- **Reduction to known characterizations.** Once $a = a'$ is characterized for a given $A$, so is $p = q$. For products, $p = q$ is a pair of equalities of the projections' $\mathsf{ap}$. For dependent functions, $p = q$ is a pointwise equality of $\mathsf{happly}(p)(x)$ and $\mathsf{happly}(q)(x)$.
- **Transport in path families** (Lemma 2.11.2). $\mathsf{transport}^{x\mapsto(a=x)}(p,q) = q \cdot p$, and $\mathsf{transport}^{x\mapsto(x=a)}(p,q) = p^{-1}\cdot q$. Transport in an identity family is concatenation.

## 5. Equality of structures (§2.14)

The payoff: *equality of mathematical structures is isomorphism*, derived rather than assumed.

A semigroup is a $\Sigma$-type:
$$\mathsf{SemigroupStr}(A) :\equiv \sum_{m : A\to A\to A}\ \prod_{x,y,z:A} m(x,m(y,z)) = m(m(x,y),z), \qquad \mathsf{Semigroup} :\equiv \sum_{A:\mathcal{U}} \mathsf{SemigroupStr}(A).$$

1. **Lifting.** Given an equivalence $e : A \simeq B$, $\mathsf{transport}^{\mathsf{SemigroupStr}}(\mathsf{ua}(e))$ is an equivalence $\mathsf{SemigroupStr}(A) \to \mathsf{SemigroupStr}(B)$. Computing it with Theorem 2.7.4 and function extensionality, it sends $m$ to $m'(b_1,b_2) = e\big(m(e^{-1}b_1, e^{-1}b_2)\big)$. This is the induced operation one would write down by hand. The induced associativity proof is a chain of equalities using $a$ and the inverse laws for $e$.
2. **Paths of semigroups.** By the characterization of paths in $\Sigma$-types (Theorem 2.7.2), $(A,m,a) = (B,m',a')$ is a pair $(p_1 : A =_{\mathcal{U}} B,\ p_2 : \mathsf{transport}(p_1,(m,a)) = (m',a'))$. By univalence $p_1 = \mathsf{ua}(e)$. Then $p_2$ reduces to
$$\prod_{x_1,x_2:A} e(m(x_1,x_2)) = m'(e(x_1), e(x_2))$$
plus a condition on the associativity proofs.
3. **Set-like case.** For *sets* (Chapter 3) any two associativity proofs are equal, so the extra condition is trivial, and equivalences are bijections. The result is the usual definition: **semigroups are equal iff isomorphic.**

The book flags that this extends to all structures built from $\Sigma$-types (the structure identity principle, §9.8).

## 6. Uniqueness of identity proofs, Axiom K, Hedberg (§7.2)

A type $X$ is a **set** when $\prod_{x,y}\prod_{p,q : x=y} p = q$. Conventional type theory calls this **UIP**. It is not an axiom here. It is a *property* some types have. $\mathbf{2}=_{\mathcal U}\mathbf{2}$ shows not all types are sets.

- **Theorem 7.2.1.** $X$ is a set iff it satisfies **Axiom K** (Streicher): $\prod_{x:X}\prod_{p : x = x} p = \mathsf{refl}_x$. Proof: K is a special case of UIP; conversely do induction on $q$ to reduce UIP to K. Again, K is a hypothesis about a particular $X$, not a rule of the theory.
- **Theorem 7.2.2.** If $R$ is a *reflexive mere relation implying identity* ($\rho : \prod_x R(x,x)$, $f : \prod_{x,y} R(x,y)\to x=y$), then $X$ is a set and $R(x,y)\simeq (x=y)$. First proof: apply $\mathsf{apd}$ to $f(x)$ to get $f(x,x,\rho(x))\cdot p = f(x,x,\rho(x))$, then cancel to get $p = \mathsf{refl}$. Second proof: show $\sum_y R(x,y)$ is contractible and use identity-system condition (iv) from §5.8.
- **Corollary 7.2.3.** If $\neg\neg(x=y)\to(x=y)$ for all $x,y$, then $X$ is a set.
- **Theorem 7.2.5 (Hedberg).** If $X$ has **decidable equality** ($\prod_{x,y}(x=y)+\neg(x=y)$) then $X$ is a set. The proof goes through Lemma 7.2.4, $(A+\neg A)\to(\neg\neg A\to A)$, and Corollary 7.2.3. Corollary: $\mathbb{N}$ is a set (Theorem 7.2.6).
- **Generalization.** For $n\ge -1$, $X$ is an $(n+1)$-type iff every $\Omega(X,x)$ is an $n$-type (Theorem 7.2.7). Equivalently, $A$ is an $n$-type iff $\Omega^{n+1}(A,a)$ is contractible for all $a$ (Theorem 7.2.9). This is what makes the truncation HIT of §7.3 work.

## 7. Grounding in code

### Lean

Lean 4's `Eq` is the same inductive family, but its universe of propositions `Prop` is *proof-irrelevant*, so UIP and Axiom K hold definitionally. The HoTT book is working in the opposite regime.

```lean
-- the inductive family, one constructor refl, A and a as parameters (based form)
inductive MyEq {α : Sort u} (a : α) : α → Prop
  | refl : MyEq a a

-- transport / indiscernibility of identicals via the eliminator
def transport {α : Type u} (C : α → Sort v) {x y : α} (p : x = y) : C x → C y :=
  fun cx => p ▸ cx

-- symmetry and transitivity are *derived* by path induction, not primitive
theorem symm' {α : Type u} {x y : α} (p : x = y) : y = x := by
  induction p; rfl
```

To get the HoTT behaviour in Lean 4 you would need an `Id` in `Type` rather than `Prop` (as in the Lean 2/HoTT-library setting). Lean 4 core also forbids mixing the two without care.

### Rust (a checker-shaped view)

The thing to notice for a checker: judgmental equality is a *function you implement* and the identity type is *data*.

```rust
enum Term {
    Var(usize),
    Id(Box<Term>, Box<Term>, Box<Term>),         // Id_A(a, b)
    Refl(Box<Term>),                             // refl_a
    // J : (C : Π x y, x=y → U) → (Π x, C x x refl_x) → Π x y p, C x y p
    J { c: Box<Term>, base: Box<Term>, x: Box<Term>, y: Box<Term>, p: Box<Term> },
    /* ... Pi, Lam, App, ... */
}

// The computation rule lives in the *definitional equality* checker:
//   J(C, c, x, x, refl_x)  ~>  c x
fn whnf(t: &Term) -> Term {
    match t {
        Term::J { base, x, p, .. } if matches!(whnf(p), Term::Refl(_)) => {
            // y must be definitionally equal to x here; the *typing* rule ensures it
            apply(base, x)
        }
        _ => t.clone(),
    }
}
```

Two checker facts follow from the book:
- `J` only reduces when the path argument is syntactically `Refl`. A stuck `J` on a variable path is normal and is why `n + 1 = 1 + n` is not judgmental.
- A *propositional* equality `p : a = b` gives the checker nothing to compute with. Only `Refl` and `≡` do. This is the same reason an SMT-backed refinement checker must pass equalities to the solver instead of treating them as rewrites.

### Python (the singleton intuition)

```python
# {y : A | a = y} is the singleton. Based path induction says any
# property of pairs (y, p) follows from the pair (a, refl).
def based_J(a, C, c):
    # only the 'a, refl' case is ever supplied; the function is total
    # over (y, p) only because p *is* produced from refl by transport
    return lambda y, p: p.transport(C, c)   # pseudo-API: p carries its own transport
```

This is a sketch: in a proof-irrelevant language the path $p$ is erased, which is exactly what the HoTT setting does *not* allow.

## 9. Relevance to the project (`type-theory`)

The topic is tagged `type-theory` only, so the connections are drawn from that area.

- **Definitional equality** (load-bearing). The split between $\equiv$ (checked by the kernel's `isDefEq`) and $=$ (a type you must construct) is the first design decision of the kernel. The $J$ computation rule is a reduction rule your `whnf`/`isDefEq` must implement. Keeping it separate from propositional equality is what keeps type checking decidable.
- **Inductive types.** The identity type is an inductive *family* with an index. Your kernel's generic recursor-generation code for indexed families (needed anyway for Lean-style inductives) already produces $J$ and based $J$. The only HoTT-specific point is that it must *not* add K or proof irrelevance. Lean's `Eq` lives in `Prop` and gets both.
- **Elaboration and metavariables.** Elaborating a $J$-eliminator requires inferring the motive $C$, which is a higher-order unification problem. Lean's elaborator handles this with `induction`/`cases` by abstracting the endpoints. The need to generalize *both* endpoints, or fix one as a parameter, is exactly the $J$ versus based-$J$ distinction in §2.2 above.
- **Dependent types, $\Sigma$-types.** Singleton contractibility $\sum_{y}(a=y)$ is how unification-style "the other side is determined" arguments (e.g. dependent pattern matching with indices) are justified type-theoretically.
- **Refinement types (flagged as a possible link, not a direct one).** A refinement $\{x : A \mid P(x)\}$ is a $\Sigma$-type, and Theorem 7.2.2 explains when equality of such subtypes is governed by the first component only (mere propositions). That is the property a refinement checker needs to treat the predicate as erasable.

Notes that do *not* bear on the project: the semigroup example (§5) and the $\Omega^n$ generalization (§6) are mathematically central to the book but are not needed for a Rust refinement-type compiler.
