## Why a calculus needs theorems, not just rules

[[The-ADCL-Calculus]] gave you seven rules and a state triple. That's a *procedure*. It is not yet a *decision procedure you can trust* — nothing so far tells you that when the procedure says "unsat," the problem really is unsatisfiable, or that it can't wedge itself into some state where no rule applies but neither `sat` nor `unsat` has been reached. This is exactly the gap between "I wrote an algorithm" and "I proved my algorithm correct," and it's the gap every trusted-kernel design has to close: a proof checker's kernel is worth nothing if its rules can be applied in a way that derives a false judgment, and a SAT/SMT solver's answer is worth nothing if "unsat" doesn't actually imply unsatisfiability.

What breaks without these theorems: without Soundness, ADCL is just a heuristic that happens to often output correct answers — you'd have no basis for trusting a single "unsat" verdict, which is disqualifying for a verification tool whose entire purpose is producing certificates other people rely on. Without the absence-of-stuck-states result, ADCL could silently hang in a state that is neither progress nor an answer, and you'd have no way to distinguish "still searching" from "will never produce anything." Without Refutational Completeness, ADCL might just never find refutations that exist, making it useless as anything but a spot-checker. And Non-Termination — perhaps counterintuitively the "negative" result — is what tells you *not* to add a naive termination check, because doing so would break Completeness.

## Soundness (Theorem 12): the two verdicts need two different arguments

$$\text{If } \Phi \leadsto^* \mathrm{sat}, \text{ then } \Phi \text{ is satisfiable. If } \Phi \leadsto^* \mathrm{unsat}, \text{ then } \Phi \text{ is unsatisfiable.}$$

These two halves are not symmetric, and the paper's proof structure reflects that directly.

**The `unsat` half is almost free.** If $\Phi \leadsto^* (\Pi, \vec\varphi, \vec B) \leadsto \mathrm{unsat}$, then by definition of Refute, $\vec\varphi \in \mathrm{sip}(\Pi)^*$ *is* a refutation — its resolvent is a conditional empty clause with a satisfiable condition. Soundness of ordinary resolution (every ground instance of a resolvent is implied by the ground instances of its parents — this is exactly the "distributes over grnd" lemma from [[Resolution-for-CHCs]]) then gives you unsatisfiability of $\mathrm{sip}(\Pi)$, hence of $\Pi$, hence — since $\Pi \equiv_A \Phi$ is an invariant maintained by every rule (Lemma 26 in the appendix: Init starts with $\Pi = \Phi$, and every subsequent addition to $\Pi$ is via Accelerate, which only ever adds a clause *equivalent* to what it replaces) — of $\Phi$ itself. One clean chain: refutation → resolution soundness → equivalence-preservation → done.

**The `sat` half requires an entirely different kind of argument** — a proof by contradiction over the *whole derivation history*, not just the final state. Assume $\Phi$ is actually unsatisfiable but the derivation reached `sat` anyway. Since $\Pi^{(m)} \equiv_A \Phi$ is unsatisfiable, and binary input resolution is complete for Horn clauses, $\mathrm{sip}(\Pi^{(m)})^*$ must contain *some* refutation $\vec\varphi$ — pick a **minimal** one with respect to a well-founded order $\succ_\Pi$ (Definition 27, discussed below). The proof then walks backward through the derivation, showing that $\vec\varphi$ must be "enabled" (not yet blocked) in the initial state (trivially true — the blocking sets start empty) but "disabled" by the final state (true because Prove only fires once everything is blocked). Somewhere along the way, $\vec\varphi$ flips from enabled to disabled — and the proof shows that *whichever rule caused that flip*, it contradicts $\vec\varphi$'s minimality: a Step can't disable it (Step never touches earlier blocking sets), an Accelerate would only disable it by making $\vec\varphi$ itself reducible to a shorter refutation via the newly-learned clause (contradicting minimality of length), and a Covered/Backtrack would only disable it by revealing $\vec\varphi$ was already non-minimal to begin with. Every case is a contradiction, so no such derivation to `sat` can exist for an unsatisfiable $\Phi$.

The reason this argument needs $\succ_\Pi$ and Lemma 28 at all — a piece of machinery `sat`-soundness alone requires — is that "the disabling rule contradicts minimality" is only a valid move if minimal refutations are guaranteed to *exist* in the first place. That's not automatic in an infinite search space; it needs a well-founded order to license "pick a minimal counterexample" as a legitimate proof technique (the same role Noetherian induction or Lean's `WellFoundedRecursion` plays whenever you need to reason about "the smallest bad thing" rather than direct induction on structure).

### The ordering $\succ_\Pi$ and why it's well-founded

**Definition 27.** For a fixed $\Pi$, $\vec\varphi_1{::}\varphi_2{::}\vec\varphi_3 \succ_\Pi \vec\varphi_1{::}\varphi{::}\vec\varphi_3$ if $\vec\varphi_2 \sqsubset \varphi$, or $\vec\varphi_2 \sqsubseteq \varphi$ and $|\vec\varphi_2| > 1$. Notice this is deliberately the same shape as the Covered rule's own applicability condition (strict redundancy for singletons, weak redundancy allowed for longer suffixes) — $\succ_\Pi$ is essentially "one Covered-shaped simplification step," lifted into an ordering relation so it can be reasoned about independently of any particular derivation.

**Lemma 28 (well-foundedness).** The proof is a clean pigeonhole argument: any infinite $\succ_\Pi$-descending chain must eventually stabilize in length (chain elements shrink in length monotonically, and $>$ on $\mathbb{N}$ is well-founded, so length can't decrease forever), which forces *some fixed position $j$* in the trace to be strictly $\sqsubset$-decreasing infinitely often. But every clause in that infinite $\sqsubset$-chain lives in $\mathrm{sip}(\Pi)$, which is **finite** (syntactic implicant projection only ever produces finitely many literal-conjunctions from a formula in negation normal form — see [[Syntactic-Implicants-and-Redundancy]]) — an infinite strictly-decreasing chain inside a finite set is a contradiction. This is the same finiteness argument that makes many termination arguments over "syntactic" objects work: the state space of *possible clauses* is finite even though the state space of *possible traces* is not, and it's specifically the trace positions, not the trace lengths, that eventually get pinned down.

In Lean, this is precisely the shape of a `WellFounded` instance built from a finiteness fact rather than a structural recursion — you'd phrase it as "there is no injection from $\mathbb{N}$ into a finite type that is also strictly monotonic under $\sqsubset$," which is `Finite.not_injective_of_lt`-flavored reasoning. If you're building a trusted kernel with mechanized soundness proofs in mind, this is the exact pattern you'd reach for: well-foundedness proofs over syntactic search states are usually finiteness arguments in disguise, not genuine induction on a decreasing measure.

## Absence of Stuck Normal Forms (Theorem 13)

$$\text{If } \Phi \leadsto^+ s \text{ where } s \text{ is a normal form w.r.t. } \leadsto, \text{ then } s \in \{\mathrm{sat}, \mathrm{unsat}\}.$$

The proof is almost a one-liner once you look at the rule set as a whole: for any state $(\Pi,\vec\varphi,\vec B)$, either the trace is empty — in which case Step or Prove is always syntactically applicable — or it's non-empty, in which case either Step or Backtrack is always applicable. There is no state shape that escapes both cases. This is exactly the "totality of the transition relation modulo terminal states" property you'd want from any well-designed abstract machine (a CEK machine, a small-step operational semantics) — every non-terminal configuration has *some* applicable step, so "stuck" and "terminal" coincide by construction rather than by accident.

**What this buys you concretely:** combined with Soundness, it means ADCL can never silently fail — if it stops, it has an answer, and that answer is correct. The only failure mode left is *not stopping at all*, which is exactly what Theorem 18 addresses.

## Refutational Completeness (Theorem 15)

$$\text{If } \Phi \text{ is unsatisfiable, then } \Phi \leadsto^*_{rs} \mathrm{unsat}.$$

Note the subscript: this is a claim about derivations *under a reasonable strategy* (see [[The-ADCL-Calculus]]'s Definition 14), not the bare calculus — completeness has to survive the restrictions imposed to rule out pathological derivations, which is not automatic (restricting a search procedure's choices can always, in principle, accidentally rule out the only path to the answer). The proof sketch is constructive: given *any* refutation $\vec\varphi$ (guaranteed to exist by completeness of resolution for unsatisfiable Horn clauses), build a reasonable derivation inductively by always choosing the Step/Accelerate that advances as far as possible along $\vec\varphi$ and picking clauses maximal with respect to $\sqsubset$ — this specific greedy choice is exactly what avoids ever triggering an unwanted Covered along the way (Covered only fires on genuinely redundant suffixes, and always choosing the $\sqsubset$-maximal available clause means you're never constructing a suffix that's redundant with respect to something *already* in $\Pi$ before you've had the chance to use it).

**The load-bearing subtlety:** completeness would *not* survive if the Reasonable Strategy's Covered mandate (condition 1) forced backtracking on *any* redundant suffix regardless of what learning happened in between — that's precisely why Definition 14 restricts the mandate to suffixes built while $\Pi$ stayed fixed. This is the same tension that shows up whenever you add pruning/subsumption to a complete search procedure: every pruning rule has to be checked against completeness, not just soundness, because an overly eager prune can throw away the only path to a correct answer.

## Non-Termination (Theorem 18): completeness and termination are not in tension

$$\text{There exists a satisfiable } \Phi \text{ such that } \Phi \not\leadsto^*_{rs} \mathrm{sat}.$$

This looks alarming next to Refutational Completeness until you notice the two theorems are about *different verdicts on different problems*: Completeness guarantees `unsat` is always reachable *for unsatisfiable problems*; nothing guarantees `sat` is reachable for satisfiable ones, and this theorem shows that gap is real, not just an artifact of a weak proof technique.

**The construction, and why it needs the mapping $L$.** The paper builds a satisfiable CHC problem $\Phi_{\text{ThueMorse}}$ that encodes the **Thue–Morse sequence** — an infinite binary(-ish) sequence famous for being *square-free*: it contains no contiguous repeated block $ww$ for any non-empty word $w$. The CHC encoding (a `ThueMorse(I,X)` predicate tracking position $I$ and value $X = w_I$, chained via a `Next` predicate) is built so that **every possible resolution sequence with $\Phi_{\text{ThueMorse}}$ is itself square-free** — no trace ever contains a repeated adjacent block $\vec\varphi{::}\vec\varphi$.

Why does square-freeness sink `sat`? Recall Accelerate only fires on a *recursive* suffix — syntactically, that means the trace contains something of the shape $\vec\varphi^\circlearrowleft$ repeated, i.e. a $ww$-block. If no resolution sequence with $\Phi$ ever contains such a block, **Accelerate can never fire**, meaning $\Pi$ can only ever grow by learning clauses whose ground-instance sets you could just as well have obtained by finitely much ordinary resolution — but since there are infinitely many square-free words to eventually reach and block, no finite $\Pi$ can ever cover them all, so Prove's precondition ("all facts/CECs blocked") can never be satisfied.

Making that last step precise is exactly what the auxiliary machinery of **Definition 16 (ADCL with Regular Languages)** is for. The mapping $L : \mathrm{sip}(\Pi) \to \mathcal{P}(\mathrm{sip}(\Phi)^*)$ associates each clause in $\Pi$ with the *regular language* of original-clause sequences whose resolvent it represents — $L(\varphi) = \{\varphi\}$ for original clauses, and $L(\mathrm{accel}(\vec\varphi^\circlearrowleft)) = L(\vec\varphi^\circlearrowleft)^+$ (Kleene-plus) for accelerated ones, since an accelerated clause stands for "any positive number of repetitions." **Lemma 17** then gives the payoff: $\mathrm{grnd}(\pi) = \mathrm{grnd}(L(\pi))$ — a clause's ground instances are exactly the ground instances of the (possibly infinite) set of original-clause sequences its $L$-language describes. This is the tool that turns "does $\Pi$ cover all resolution sequences with $\Phi$" into a question about regular languages, where finiteness arguments (like Lemma 28's) actually apply: $L(\Pi)$ can only ever contain **finitely many square-free words** at any reachable state (it's built from finitely many singleton languages, concatenation, and Kleene-plus over a finite alphabet of original clauses — a standard closure fact about regular languages), yet $\Phi_{\text{ThueMorse}}$ has infinitely many pairwise-different square-free ground instances to cover. Contradiction — $\Phi_{\text{ThueMorse}} \not\leadsto^*_{rs} \mathrm{sat}$.

The elegance here is worth pausing on: $L$ isn't introduced merely as a *proof device*. Section 4 (see [[Implementing-ADCL-in-LoAT]]) reuses this exact regular-language machinery as LoAT's actual redundancy-checking mechanism (finite-automaton language inclusion) — the same structure that proves the calculus incomplete-in-general for `sat` is also the practical tool that makes checking redundancy for `unsat` tractable.

**The upshot for a strategy designer:** don't add a naive "if we've been searching for $N$ steps without acceleration firing, give up and try something else" heuristic and expect it to preserve correctness in general — non-termination here isn't a bug to route around with a timeout, it's a genuine, unavoidable consequence of Refutational Completeness plus the undecidability of CHC-SAT over theories like LIA. (The paper is explicit that this isn't merely "CHC-SAT is undecidable, so of course a sound complete procedure doesn't terminate" — ADCL's oracles for SMT, redundancy, and acceleration are *assumed*, so the argument has to be self-contained rather than borrowed wholesale from undecidability of the underlying theory.)

## Where this leads

These four theorems are what make [[The-ADCL-Calculus]] a calculus worth implementing rather than just an interesting idea — [[Implementing-ADCL-in-LoAT]] is entirely about how to realize these idealized, oracle-assuming guarantees with real (incomplete) SMT queries and automaton-based redundancy checks, deliberately trading some of this section's exactness for tractability (and explicitly sacrificing the `sat` direction, since LoAT's approximations are unsound for it — see [[Implementing-ADCL-in-LoAT]]). The empirical payoff of trusting these proofs shows up directly in [[Empirical-Evaluation]]'s refutation-length numbers: every one of those dramatically shortened proofs is only meaningful *because* Soundness guarantees it's a real proof, not an artifact of a heuristic that happened to terminate early.

For the standing project (`automated-reasoning`): this is close to the canonical shape a **trusted-kernel correctness argument** needs to take for the theorem-prover component — a soundness theorem split by verdict (because different verdicts often really do need different proof techniques, as here), an explicit "can't get stuck" totality result, a completeness theorem stated relative to whatever strategy restrictions you actually implement (not the unrestricted calculus), and — if the procedure isn't guaranteed to terminate — a clear-eyed non-termination result rather than a hand-wave, so that a timeout in the real implementation is understood as "we ran out of patience," never silently reinterpreted as "we proved something." The $\succ_\Pi$/finiteness pattern for well-foundedness, and the $L$-as-regular-language technique for turning a semantic covering question into a decidable automaton-inclusion question, are both directly reusable proof techniques for the CSP kernel's own soundness argument.
