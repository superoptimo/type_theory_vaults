# Regular Tree Grammars and Expressions

[[book-guidelines|↩ Back to guidelines]]

## Why generate, when you already know how to accept?

Chapter 1 gave you tree automata: machines that *accept or reject* a term you hand them. That's the acceptor's view of a language — useful for deciding membership, but it doesn't tell you how to *produce* the elements of that language in the first place. If you've ever written

```ml
type Nat = Zero | Succ of Nat
type List = Nil | Cons of Nat * List
```

you've already written a generator, not an acceptor. This is exactly a **tree grammar** in disguise — `List` and `Nat` are non-terminals, `Nil`/`Cons`/`Zero`/`Succ` are terminals, and each ADT constructor line is a production rule. Chapter 2's opening move is to formalize this correspondence and then prove something that isn't obvious at all: the set of languages you can *generate* this way is *exactly* the set of languages you can *accept* with a tree automaton. Generative and acceptor views of regularity coincide for trees just as they do for words — but trees earn that equivalence, they don't inherit it for free, and this chapter is where the earning happens.

## Tree grammars, formally

A **tree grammar** is a tuple $G = (S, N, F, R)$: an axiom $S$, non-terminals $N$ (with $S \in N$), terminals $F$, and rules $R$ of the form $\alpha \to \beta$ where $\alpha, \beta \in T(F \cup N \cup X)$ ($X$ a set of dummy variables), $\alpha$ containing at least one non-terminal, $F \cap N = \emptyset$, every symbol carrying a fixed arity, and $S$ of arity 0.

This chapter restricts attention to **regular tree grammars**: all non-terminals have arity 0, and rules look like $A \to \beta$ with $A \in N$ a single non-terminal and $\beta \in T(F \cup N)$. (Full tree grammars, where non-terminals can themselves take arguments, come back in §2.5 as *context-free* tree grammars — strictly more expressive, and covered separately.)

```rust
enum RhsSymbol<'a> { Terminal(&'a str, Vec<usize>), NonTerminal(usize) }
// A rule: NonTerminal(A) -> tree built from RhsSymbol nodes
struct Rule { lhs: usize, rhs: Tree }
struct RegularTreeGrammar { axiom: usize, rules: Vec<Rule> }
```

The **derivation relation** $\to_G$ replaces a non-terminal occurrence by a rule's right-hand side: $s \to_G t$ iff $s = C[A]$, $t = C[\alpha]$ for some rule $A \to \alpha$ and context $C$. $L(G)$ is the set of ground terms reachable from $S$ by $\to_G^+$. This is precisely the same "rewrite the hole" idea as $\beta$-reduction rewriting a redex inside a context — a theme that will recur every time you need a congruence closed under contexts.

**Cleaning up grammars.** A non-terminal is *reachable* if some derivation from $S$ passes through it, and *productive* if it derives at least one ground term. A grammar is **reduced** iff every non-terminal is both. Proposition 2.1.3 gives an explicit two-pass fixed-point computation for reducing any grammar: first compute the productive set $N_{\mathrm{Prod}} = \bigcup_n \mathrm{Prod}_n$ (a monotone increasing sequence, so it stabilizes), keep only rules using productive non-terminals, *then* — on the resulting grammar — compute the reachable set the same way. The book flags an easy trap here: swapping the order of the two passes can produce an *unreduced* grammar (a reachable-but-unproductive non-terminal, discarded in the wrong pass, can leave behind rules referencing now-dead non-terminals). This two-pass discipline — "prune dead code, then prune unreachable code, and mind the order" — is the tree-grammar analogue of a compiler's liveness/reachability dead-code elimination pass, and the order-dependence bug is exactly the kind of subtle invariant a Rust implementation needs to get right rather than "clean until nothing changes."

Every regular tree grammar is further reducible to a **normalized** one, where rules take the shape $A \to f(A_1,\dots,A_n)$ or $A \to a$ (Proposition 2.1.4) — no rule directly names a compound term with non-non-terminal children, and no unit rules $A_1 \to A_2$ survive (those get transitively inlined). Normalization is the tree-grammar equivalent of Chomsky normal form, and just like there, it buys uniform proof arguments later at essentially no expressive cost.

### Regularity = recognizability (Theorem 2.1.5)

The chapter's first payoff: **a tree language is recognizable (Chapter 1's automaton-acceptable sense) if and only if it is regular (generated by some regular tree grammar).**

Both directions are mechanical once you see the trick, and the trick is: *states and non-terminals are the same data, viewed from opposite ends.*

- **Grammar → automaton (top-down):** given normalized $G$, build $\mathcal{A} = (Q, F, I, \Delta)$ with $Q = \{q_A \mid A \in N\}$, $I = \{q_S\}$, and a transition $q_A(f(x_1,\dots,x_n)) \to f(q_{A_1}(x_1),\dots,q_{A_n}(x_n))$ for every rule $A \to f(A_1,\dots,A_n)$. Reading a rule top-down *is* reading a top-down-automaton transition.
- **Automaton → grammar:** given a top-down $\mathcal{A}$, mint one non-terminal $A_q$ per state $q$, and mirror each transition as a rule $A_q \to f(A_{q_1},\dots,A_{q_n})$, with $S \to A_q$ for initial $q$.

```lean
-- The correspondence as a bijection-shaped statement (schematic):
-- states of a top-down automaton  ≅  non-terminals of a regular tree grammar
-- a transition  q(f(x₁,…,xₙ)) → f(q₁(x₁),…,qₙ(xₙ))  ≅  a rule  A_q → f(A_{q₁},…,A_{qₙ})
theorem regular_iff_recognizable (L : Set (Term F)) :
    IsRegularTreeLanguage L ↔ IsRecognizable L := by
  constructor
  · intro ⟨G, hG⟩; exact ⟨grammarToAutomaton G, hG⟩
  · intro ⟨A, hA⟩; exact ⟨automatonToGrammar A, hA⟩
```

**[[Automata-with-Constraints#What breaks|What breaks]] without normalization:** if you tried this construction on an un-normalized grammar (rules like $A \to f(g(B), c)$ with nested structure on the right), you'd need automaton transitions that inspect several levels of structure per step — which isn't what a tree automaton transition *is* (one function symbol per move). Normalization is precisely what makes "one rule = one transition" a valid translation.

## Regular expressions and Kleene's theorem for trees

Word regular expressions build languages by union, concatenation, and iteration — but "concatenation" and "iteration" for words tacitly assume there's only one place to attach the next piece: the end. Trees have no privileged single attachment point; a tree can have many leaves, and "iterate here but not there" needs to be said explicitly. TATA's answer: introduce a distinguished set of placeholder constants $K = \{\square_1, \square_2, \dots\}$ (arity 0, disjoint from $F$) that mark exactly where substitution should happen.

**Tree substitution.** Given a tree $t$ over $F \cup K$ and languages $L_1,\dots,L_n$, the substitution $t\{\square_1 \leftarrow L_1, \dots, \square_n \leftarrow L_n\}$ replaces every $\square_i$-leaf independently by *some* member of $L_i$ — different occurrences of the same $\square_i$ can be filled by different terms. This is subtly different from ordinary term substitution (which plugs in one fixed term everywhere), and the difference is exactly what makes it a language-building operation rather than a single-tree operation:

$$
\square_i\{\square_1\!\leftarrow\!L_1,\dots\} = L_i, \quad
a\{\dots\} = \{a\} \ (a \ne \square_j),\quad
f(s_1,\dots,s_n)\{\dots\} = \{f(t_1,\dots,t_n) \mid t_i \in s_i\{\dots\}\}
$$

From substitution you get **concatenation through a hole**, $L \cdot_\square M = \bigcup_{t \in L} t\{\square \leftarrow M\}$, and **iteration**, built as an increasing chain $L^{0,\square} = \{\square\}$, $L^{n+1,\square} = L^{n,\square} \cup L \cdot_\square L^{n,\square}$, with closure $L^{*,\square} = \bigcup_n L^{n,\square}$.

```rust
// Regexp(F, K): the tree analogue of a regex AST, but with a hole-symbol
// tag on the concatenation/iteration nodes to say *where* the recursion attaches.
enum RegExpr {
    Empty,
    Sym(SymbolId),                              // a ∈ F0 ∪ K
    App(SymbolId, Vec<RegExpr>),                 // f(E1, ..., En)
    Union(Box<RegExpr>, Box<RegExpr>),           // E1 + E2
    Concat(Box<RegExpr>, HoleId, Box<RegExpr>),  // E1 .□ E2
    Star(Box<RegExpr>, HoleId),                  // E*,□
}
```

Regularity is preserved by all these operations (Propositions 2.2.3, 2.2.4 — both by direct grammar surgery: reroute the rules that used to produce $\square_i$ to instead branch into $L_i$'s own grammar). Combined with a Kleene-style translation from a bottom-up automaton into a regular expression (Proposition 2.2.7, built by the classic subset-decomposition argument $T(i,j,K)$ = "reachable at state $q_i$ using only states $\le q_j$ below") this gives **Theorem 2.2.8 (Kleene's theorem for trees): a tree language is recognizable iff it is denoted by a regular tree expression.**

The list-of-naturals example from earlier crystallizes as
$$
\mathit{Nat} = s(\square_1)^{*,\square_1}.\square_1\, 0, \qquad
\mathit{List} = \mathrm{nil} + \mathrm{cons}(s(\square_1)^{*,\square_1}.\square_1\, 0,\ \square_2)^{*,\square_2}.\square_2\, \mathrm{nil}
$$
— which reads exactly like `Nat*` and `List*` in a word-regex sense, once you accept that $\square_1$ names "the Nat-hole" and $\square_2$ names "the List-hole."

## Regular equation systems: the fixed-point view

There's a third equivalent presentation, and it's the one with the most mileage for anything you build later: a system of **regular equations**

$$
X_1 = s_{11} + \dots + s_{1m_1}, \qquad \dots, \qquad X_p = s_{p1} + \dots + s_{pm_p}
$$

where each $s_{ji}$ is a term over $F \cup \{X_1,\dots,X_n\}$. A *solution* is an $n$-tuple of languages satisfying all equations simultaneously (with each $X_k$ on the right substituted by $L_k$). Crucially, solutions aren't unique — $(T(F), \dots, T(F))$ trivially solves almost anything — so the definition that matters is the **least** solution under the pointwise-inclusion order on $T(F)^n$.

To construct it, define the operator $TS: T(F)^n \to T(F)^n$,
$$
TS(L_1,\dots,L_n) = \Big(L_1 \cup \bigcup_i s_{1i}\{X_1\!\leftarrow\!L_1,\dots\},\ \dots\Big)
$$
Proposition 2.3.3 shows $TS$ is **continuous** (monotone, and commutes with unions of increasing chains), so by the **Knaster–Tarski theorem**, its least fixed point $TS^\omega(\emptyset,\dots,\emptyset) = \bigcup_n TS^n(\emptyset,\dots,\emptyset)$ *is* the least solution — and Theorem 2.3.4 proves this least-fixed-point tuple is exactly the tuple of languages generated by treating each equation as a grammar's rule set for that non-terminal. Three completely different-looking definitions — automaton acceptance, grammar generation, least fixed point of a monotone set operator — turn out to be one object viewed three ways.

```lean
-- The shape of the argument, abstractly: a monotone continuous operator on a
-- complete lattice of tree-language tuples has a least fixed point reached by
-- iterating from ⊥, and Knaster–Tarski is the reason the iteration terminates
-- "in the limit" even when no finite iterate is exact yet.
theorem knaster_tarski_least_fixedpoint
    {L : Type*} [CompleteLattice L] (f : L →o L) :
    f (sInf {x | f x ≤ x}) = sInf {x | f x ≤ x} := OrderHom.map_lfp f
```

**Why this matters beyond trees:** this is the *exact* computational pattern behind abstract interpretation's invariant generation. An abstract-interpretation analysis is a monotone transfer function over an abstract domain (a lattice, just like $T(F)^n$ under $\subseteq$), and the invariant you compute is its least fixed point, reached by Kleene iteration from bottom — often accelerated with widening when the lattice has infinite ascending chains, which $T(F)^n$ generally does. If you're planning to implement a CHC-style abstract-interpretation kernel, this section is the cleanest possible finite-alphabet warm-up for that machinery: the fixed-point operator, the continuity argument, and the "iterate from $\emptyset$" construction are literally the same shape you'll reuse when the lattice is intervals, octagons, or predicate abstractions instead of tree languages.

## Yield and the connection to context-free word languages

A natural question: word grammars and tree grammars both use the word "context-free"/"regular" — are they secretly the same theory? Almost, but with a genuinely informative gap.

The **Yield** operator reads a tree's leaves left to right: $\mathrm{Yield}(a) = a$ for $a \in F_0$, $\mathrm{Yield}(f(s_1,\dots,s_n)) = \mathrm{Yield}(s_1)\cdots\mathrm{Yield}(s_n)$. Given a context-free word grammar, its **derivation trees** — with a fresh symbol $(A, m)$ for each production of length $m$, so that arity tracks "how many children this production rule produces" — form a *tree* language, and reading the leaves of a derivation tree recovers exactly the word it derived.

**Theorem 2.4.3** ties the two worlds together in three parts:
1. The derivation trees of any context-free word grammar form a **regular tree language** (translate each production into a normalized tree-grammar rule keyed by the $(A,m)$ symbol).
2. For any regular tree language $L$, $\mathrm{Yield}(L)$ is a **context-free word language**.
3. But **not every regular tree language is a set of derivation trees** — the classes are not the same.

Part 3 is the interesting direction, and the book's own example makes the gap concrete. Consider the regular tree grammar $S \to s(G_1, G_2)$, $G_1 \to g(a)$, $G_2 \to g(b)$, which generates the *single* tree $s(g(a), g(b))$. If this were the derivation-tree language of some context-free word grammar, then reaching the root would require a rule $S \to G\,G$ for a *single* non-terminal $G$ used twice, together with rules $G \to a$ and $G \to b$ — but then $S(G(a), G(a))$ would *also* have to be generated (nothing distinguishes the two $G$ occurrences), which it isn't. The tree $s(g(a),g(b))$ needs its two children to be generated by *different* rules even though they look structurally identical — something a context-free grammar's flat "one non-terminal, reused freely" derivation trees (called **local tree languages**) simply cannot express.

The resolution: **every regular tree language is the image of a local tree language under an alphabetic homomorphism** (a homomorphism mapping each symbol to a term of matching arity built from fresh variables, essentially a relabeling). Concretely: take derivation trees over *distinguishable* non-terminals $G_1, G_2$ (grammar $S \to G_1 G_2$, $G_1 \to a$, $G_2 \to b$, generating the single local tree $S(G_1(a), G_2(b))$), then apply the homomorphism $h_F(S) = s(x_1,x_2)$, $h_F(G_1) = g(x_1)$, $h_F(G_2) = g(x_1)$ to relabel it into exactly $s(g(a), g(b))$. In other words: local (derivation-tree) languages under-distinguish symmetric-looking positions; recognizable languages recover that missing distinguishing power via a renaming step *after* generation, not during it.

## Where this leads

This section sits at the algebraic heart of the book: everything downstream — context-free tree languages (§2.5, next topic, where nonterminals themselves take arguments and the IO/OI evaluation-order split appears) and the Chapter 3 correspondence between recognizable tree languages and *definable* sets in weak monadic second-order logic — leans on the fact that "generate," "accept," and "least fixed point of a monotone equation system" name the same three-way equivalence proved here. The regular-equation-system view in particular is worth carrying forward explicitly: it's the same fixed-point-on-a-lattice pattern that drives abstract interpretation's invariant computation and the least-model semantics of constrained Horn clauses — when you get to implementing a CHC solver, you are, structurally, iterating $TS$ again, just over a richer lattice than tree languages.

The local-vs-regular gap from §2.4 is also worth flagging forward: it's the first place in the book where "generated by a grammar with a fixed non-terminal vocabulary" turns out to be *strictly weaker* than "recognized by an automaton with the same-size state set" — a distinction that resurfaces, in a much sharper form, when §2.5's IO vs. OI derivation strategies diverge exactly on non-linear grammars.
