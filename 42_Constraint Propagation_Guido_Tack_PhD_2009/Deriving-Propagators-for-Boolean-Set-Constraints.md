# Deriving Propagators for Boolean Set Constraints

## The problem this chapter refuses to solve by hand

[[Views-and-Derived-Propagators|Chapters 7–9]] solved "don't hand-write every propagator variant" by transforming propagators you already have. But that trick needs a base case: *somebody* still has to hand-write the first implementation of intersection, union, complement, equality, disjointness, partition… And [[Range-Iterators-for-Set-Valued-Domain-Operations|Chapter 10]] closed on an uncomfortable empirical finding: chaining views to build one operation out of another (e.g. getting union for free by complementing an intersection view) is *provably* suboptimal, and the compiler cannot rescue it — 16–47% overhead survives inlining and constant-folding, because a chain of views does genuinely more work than a purpose-built algorithm, not just differently-shaped work.

So Chapter 11 asks a different question than "how do I reuse a propagator I already have," and instead asks: **can I skip hand-writing propagators for an entire *class* of constraints, by writing down a specification of the constraint and mechanically deriving both a propagation algorithm and a completeness proof from it?** The class chosen is *Boolean set constraints* — the family built from set equality, subset, union, intersection, and complement (exactly the operations of Section 2.3's Sudoku-as-set-CSP and Social Golfer examples). This is a strictly more ambitious claim than a view: a view transforms *one* propagator's interface; this chapter *compiles* an entire propagator's logic out of algebraic structure alone.

**[[The-Denotational-and-Operational-Model-of-Constraint-Propagation#What breaks without this|What breaks without this]].** The alternative is the literature's actual practice up to this point: "ad hoc rules for a few basic constraints such as intersection or union" (Tack's own words), each proved sound and complete by a bespoke argument, each implemented by hand, with a new proof and a new implementation required every time a solver wants one more constraint variant (subset-with-offset, partition-with-three-parts, reified disjointness…). That doesn't scale, and worse, it offers no guarantee that a proof technique that worked for intersection will generalize — every new constraint restarts the argument from zero. Chapter 11's payoff is a single theorem that, applied mechanically to *any* Boolean set expression, produces a $\mathcal D^{[\mathcal P(U)]}$-complete (set-interval-complete, in the sense of [[Propagation-Strength-and-Domain-Approximations]]) propagator with no further proof obligation.

## The specification language: Boolean set constraints

A **Boolean set constraint** is generated by the grammar

$$
C ::= S = S \mid S \subseteq S \mid C \wedge C, \qquad S ::= x \mid \emptyset \mid U \mid S \cap S \mid S \cup S \mid \overline S
$$

— set variables, the empty set, the universe, intersection, union, complement, chained through equality, subset, and conjunction. Semantics is the obvious lift of an assignment $a$ (mapping variables to subsets of a finite universe $U$) to expressions:

$$
a(S_1 \cap S_2) := a(S_1) \cap a(S_2), \quad a(S_1 \cup S_2) := a(S_1) \cup a(S_2), \quad a(\overline S) := \overline{a(S)}
$$

and to constraints via $a \models S_1 = S_2 :\Leftrightarrow a(S_1)=a(S_2)$, etc. The induced set of satisfying assignments is written $\llbracket C \rrbracket$. This grammar is the same shape as [[Views-and-Derived-Propagators|the earlier "same algorithm, different sign" observation]], but generalized to a whole algebra rather than one derivation at a time: union, intersection, and complement of sets form a **Boolean algebra**, with union as disjunction, intersection as conjunction, and complement as negation. Every equivalence you already trust for propositional logic (De Morgan, distributivity, double negation…) transfers verbatim to set expressions — and that transfer is the entire engine driving the rest of the chapter.

**Rust [[The-Denotational-and-Operational-Model-of-Constraint-Propagation#Grounding|grounding]].** The AST for $S$ and $C$ is a completely unremarkable recursive enum — this is a place where letting the type system carry the grammar is the whole point:

```rust
enum SetExpr {
    Var(VarId),
    Empty,
    Universe,
    Inter(Box<SetExpr>, Box<SetExpr>),
    Union(Box<SetExpr>, Box<SetExpr>),
    Compl(Box<SetExpr>),
}

enum Constraint {
    Eq(SetExpr, SetExpr),
    Subset(SetExpr, SetExpr),
    And(Box<Constraint>, Box<Constraint>),
}
```

If your own CSP kernel is going to compile declarative constraint specifications the way this chapter does, this enum — plus the normal-form transformations below — *is* the front end of that compiler.

## Equation normal form: collapsing everything to one equation

The first mechanical step exploits the Boolean-algebra structure directly: **any** conjunction of equations and subset relations is equivalent to a *single* equation $S = U$, called **equation normal form (ENF)**, via three identities:

$$
S_1 = S_2 \equiv S_1 \subseteq S_2 \wedge S_2 \subseteq S_1, \qquad S_1 \subseteq S_2 \equiv S_1 \cup \overline{S_2} = U, \qquad S_1 = U \wedge S_2 = U \equiv S_1 \cap S_2 = U
$$

Chain these and the grammar's $\wedge$ disappears entirely — a constraint $C$ becomes one expression $S=U$ with $\llbracket S=U\rrbracket = \llbracket C\rrbracket$. For example, subset $x \subseteq y$ becomes $x \cup \overline y = U$; equality $x=y$ becomes $(\overline x \cup y) \cap (x \cup \overline y) = U$; the ternary partition $x = y \uplus z$ (i.e. $x = y \cup z \wedge y \cap z = \emptyset$) becomes $(\overline x \cup y \cup z) \cap (x \cup \overline y \cup \overline z) \cap \overline y \cup \overline z = U$. From this point forward, *every* constraint the chapter reasons about is uniformly a single equation $S=U$ — the multi-relation surface syntax was only ever sugar.

## Variable isolation via Shannon expansion

This is the chapter's central algebraic move, and it directly answers a claim from the literature that Tack explicitly refutes in Section 11.6: Gervet (2006) argues that because $\cup, \cap, \setminus$ have no inverse operations, "there is no way to move all the operation symbols on one side of the constraint relation." That's true in general algebra — but it's false specifically for the *set-interval approximation*, and the reason is Shannon's expansion. For any expression $S$ and any variable $x$, writing $S[a/x]$ for $S$ with $x$ substituted by $a$:

$$
S = (x \cup S[\emptyset/x]) \cap (\overline x \cup S[U/x])
$$

This is exactly the Boolean-logic identity $f = (x \wedge f|_{x=1}) \vee (\neg x \wedge f|_{x=0})$ read through the union-is-or, intersection-is-and dictionary — the same case-split every SAT solver and BDD package performs when branching on a variable, just phrased in set notation. Substitute this into an ENF $S=U$ and translate back through the ENF identities:

$$
S = U \;\equiv\; S[\emptyset/x] \subseteq x \;\wedge\; x \subseteq S[U/x]
$$

Since $x$ has been eliminated from both $S[\emptyset/x]$ and $S[U/x]$ by construction, this is an interval that **encloses** $x$ — Tack calls it the **$x$-interval normal form**, $\mathrm{INF}_x$, written

$$
S[\emptyset/x] \subseteq x \subseteq S[U/x]
$$

**What breaks without this.** Without variable isolation, a propagator can only ever evaluate a constraint's *satisfaction*, never derive a *bound update* — you'd know whether a candidate assignment works, but not which values to prune. $\mathrm{INF}_x$ is what turns "is this constraint satisfied" into "here is the exact greatest-lower/least-upper bound $x$ is allowed to have," which is precisely the shape a propagator's output needs.

**Worked example (intersection, Ex. 11.2).** For $x = y \cap z$:

$$
x = y \cap z \;\equiv\; (\overline x \cup (y\cap z)) \cap (x \cup \overline{y \cap z}) = U \quad\text{(ENF)}
$$
$$
\equiv\; y \cap z \subseteq x \subseteq y \cap z \quad (\mathrm{INF}_x), \qquad \overline x \subseteq y \subseteq (x \cup z)\cap(x\cup\overline z) \quad (\mathrm{INF}_y)
$$

Notice $\mathrm{INF}_x$ collapses to an *equality* ($y\cap z \subseteq x \subseteq y\cap z$ forces $x = y\cap z$) — exactly what you'd hand-derive for intersection, but here it falls straight out of the general machinery, no bespoke argument required.

**Worked example (partition, Ex. 11.3).** For $x = y \uplus z$ (disjoint union):

$$
\mathrm{INF}_x:\; (\overline y \cup \overline z) \cup (y \cap z) \subseteq x \subseteq (\overline y \cup \overline z) \cap \overline y \cup \overline z
$$

(the book gives $\mathrm{INF}_y$ and $\mathrm{INF}_z$ too, each one symmetric). Every single one of the three interval normal forms *separately* forces $y$ and $z$ to be disjoint — $\mathrm{INF}_x$ does it by transitivity, since its lower bound already requires $y \cup z \subseteq (y \cup z) \cap \overline y \cap \overline z$. That redundancy is not wasted work: it's exactly what lets each variable's propagator run independently and still jointly enforce the whole constraint, which is the property the next section formalizes.

## The propagator and its completeness proof

Given $S=U$ in ENF, define for each variable $x$ appearing in $S$:

$$
\mathrm{glb}(S,x,d) := \bigcap_{a\in d} a(S[\emptyset/x]), \qquad \mathrm{lub}(S,x,d) := \bigcup_{a\in d} a(S[U/x])
$$

and the propagator

$$
p_S(d)(x) := \big[\, \mathrm{glb}(d(x)) \cup \mathrm{glb}(S,x,d),\; \mathrm{lub}(d(x)) \cap \mathrm{lub}(S,x,d) \,\big]
$$

This is a *specification*, not yet an algorithm — $\mathrm{glb}$/$\mathrm{lub}$ as written range over all assignments $a \in d$, which is exponential. But the chapter's centerpiece, **Theorem 11.9**, proves $p_S = p_S^{\max}$: $p_S$ is exactly the *canonical* propagator from [[Propagation-Strength-and-Domain-Approximations|Section 4.5]] — the strongest $\mathcal D^{[\mathcal P(U)]}$-complete propagator for $\llbracket S=U\rrbracket$ that exists. The proof chains four lemmas, and the chain is worth understanding in outline because it's a template, not just a one-off argument:

- **Lemma 11.4 (continuity).** Changing an assignment $a$ at one variable by a single value $v$ changes $a(S)$ by at most that same value $v$. (Structural induction on $S$: adding/removing $v$ to a union/intersection argument can only add/remove $v$ from the result — it can never introduce or delete *other* elements.) This is the load-bearing fact that lets the proof reason "one value at a time" throughout.
- **Lemma 11.5 (merging).** Given two licensed assignments $a, a' \in d$ where $a'$ contributes a value $v \notin a(S)$, you can *construct* a third licensed assignment $a'' \in d$ with $a''(S) = a(S)\cup\{v\}$, by copying just the literals responsible for $v$ from $a'$ into $a$. This is what makes the bound-over-all-assignments actually *achievable* by a single witness assignment, not just an abstract supremum.
- **Lemma 11.6 (bound realizability).** Consequently, there's always a single assignment $a' \in d$ that simultaneously realizes the *entire* union $\bigcup_{a \models x \subseteq S[U/x]} a(x)$ — the sup is a max, attained.
- **Lemmas 11.7–11.8 (bound decomposition).** These are the two steps that actually replace "all assignments satisfying $S=U$" with "assignments satisfying just the lower bound, and assignments satisfying just the upper bound" (11.7), and then replace *that* with "current domain bound $\cap$/$\cup$ the bound of $S[U/x]$ alone" (11.8) — precisely the decomposition that turns an intractable quantification over assignments into an expression computable from $d(x)$ and $S[U/x]$ directly.

Composing these four lemmas is literally the proof of Theorem 11.9 — each equality in the chain is one lemma, ending at $p_S(d)(x) = [\mathrm{glb}(d(x)) \cup \mathrm{glb}(S,x,d),\, \mathrm{lub}(d(x))\cap\mathrm{lub}(S,x,d)]$, which is definitionally $p_S$. **The proof pattern to carry forward:** continuity + witness-construction + bound-decomposition is a reusable recipe any time you need to show a locally-computable formula equals a globally-quantified supremum/infimum over a structured search space — the same shape recurs in completeness arguments for abstract-interpretation lattices.

## From specification to algorithm: literals, not assignments

Theorem 11.9 says $p_S$ *is* the right propagator; it doesn't yet say how to *compute* $\mathrm{glb}$/$\mathrm{lub}$ without enumerating assignments. The final piece: put $S[U/x]$ into **disjunctive normal form** (DNF), a union of conjunctive clauses of literals ($y$ or $\overline y$). Then $\bigcup_{a\in d} a(S[U/x])$ distributes over the DNF's outer union, and for each clause, either it contains a complementary pair ($y$ and $\overline y$) — in which case that clause contributes $\emptyset$ and drops out — or the *single* assignment $a_{\max} \in d$ that sets every literal to its maximum ($\mathrm{lub}(d(y))$ for $y$, $\mathrm{glb}(d(y))$ for $\overline y$) dominates all other assignments on that clause, by monotonicity of intersection. So:

$$
\mathrm{lub}(S,x,d) = \bigcup_{\text{clauses}} \bigcap_{\text{literals } L \text{ in clause}} \mathrm{bound}(L,d)
$$

— a formula built entirely from **per-variable bound lookups**, dually for $\mathrm{glb}$ via conjunctive normal form (CNF) of $S[\emptyset/x]$. This is the step that makes the whole theory *implementable*: `lub`/`glb` reduce to set-valued unions and intersections of variable bounds, exactly the [[Range-Iterators-for-Set-Valued-Domain-Operations|range-iterator machinery]] Chapter 10 built. The trade-off is explicit and unavoidable: converting to DNF/CNF is worst-case exponential *in the number of variables* (never in the size of the universe $U$) — and the book is upfront that this is not an accident of a suboptimal algorithm, it's the propagator naturally deciding Boolean satisfiability, an NP-complete problem, whenever it fully evaluates a clause.

**Worked example (Ex. 11.10, partition's lower bound on $y$).** From $\mathrm{INF}_y$'s lower bound $S[\emptyset/y] = (\overline x \cap \overline z) \cup (x \cap z)$, converting to CNF gives $(\overline x \cup \overline z) \cap (x \cup z)$, and since neither conjunct is trivial, this reduces directly to bound lookups:

$$
\big(\mathrm{glb}(d(x)) \cup \mathrm{glb}(d(z))\big) \cap \big(\mathrm{lub}(d(x)) \cup \mathrm{lub}(d(z))\big)
$$

— a formula any range-iterator implementation computes in linear time in the size of the involved bounds.

## Negation: real expressivity, a genuinely new propagation rule

The grammar above has no disequality or set difference — a real gap, since it can't express $S_1 \neq S_2$. Is that a shortcoming that's easy to patch by just adding $\llbracket S \neq \emptyset\rrbracket$ as sugar? **Theorem 11.11 says no, structurally**: for $|U|>1$, a nontrivial negative constraint $\llbracket S\neq\emptyset\rrbracket$ can *never* be rewritten as some positive constraint $\llbracket T=U\rrbracket$. The proof constructs, for any candidate positive constraint whose CNF has a non-trivial conjunct, a witness assignment that satisfies the negative constraint but fails that conjunct — so no positive $T$ can match. This means negation is a genuine increase in expressive power, not a notational convenience, and it has to be handled by its own propagation rule.

That rule, via Shannon expansion again: $\llbracket S \neq \emptyset \rrbracket \equiv \llbracket (S[\emptyset/x]\cap x) \cup (S[U/x]\cap \overline x) \neq \emptyset\rrbracket$. A negative constraint can only prune $x$ under one specific circumstance — when exactly one candidate witness value $v$ remains that could keep the disjunction non-empty:

$$
\bigcup_{a\in d} a(S[\emptyset/x]) \cap \mathrm{glb}(d(x)) = \emptyset \;\wedge\; \mathrm{lub}(d(x)) \cap \bigcup_{a\in d}a(S[U/x]) = \{v\} \implies v \text{ must enter the lower bound of } x
$$

(with a mirrored rule for excluding $v$ from the upper bound). If *both* disjuncts are already empty, propagation detects **failure** outright. This is a fundamentally different pruning shape than the positive case's "compute a whole new bound" — here the propagator can only ever fire on *singleton* witness sets, which is exactly why the technique from the section above (bound formulas from literals) still applies to compute the two unions, but the pruning trigger itself is qualitatively sparser.

**[[Efficient-Propagator-Scheduling#Subsumption|Subsumption]] and reification fall out for free.** A propagator is subsumed once its constraint is *entailed* — and entailment of $\llbracket S=U\rrbracket$ by $d$ is exactly *failure* of $\llbracket S\neq\emptyset\rrbracket$'s negation-propagation check above. So the very same machinery that propagates negation also decides subsumption/entailment of the positive constraint, and that's precisely what's needed to implement **reification** ($C \leftrightarrow b$ for a control Boolean $b$): detect entailment of $C$ to set $b=1$, detect entailment of $\neg C$ to set $b=0$. One mechanism, two uses. The chapter is candid about the remaining gap: *mixed* positive/negative conjunctions like strict subset ($x \subset y \equiv x\subseteq y \wedge x\neq y$) fall outside the language entirely and require stitching together two separate propagators, possibly losing set-interval completeness — flagged explicitly as future work in Section 12.2.

## Linear time for n-ary constraints: common subexpression elimination

Naively, an $n$-ary Boolean set constraint (e.g. $y = \bigcup_{1\le i\le n} x_i$) costs $O(n^2)$: each of the $n{+}1$ variables' interval normal forms has size $O(n)$, so the total work summed across all variables is quadratic (Example 11.12). The fix generalizes the classic "prefix/suffix product" trick to set expressions. For $y=\bigcup_i x_i$, each $x_i$'s lower bound is $\mathrm{glb}(d(y)) \cap \bigcap_{j\ne i}\mathrm{lub}(x_j)$ — an intersection over all *other* variables. Precompute a suffix table $\mathrm{right}[i] := \bigcap_{j>i}\mathrm{lub}(x_j)$ once, in $O(n)$, then propagate $x_1,\dots,x_n$ in order while maintaining a running prefix $\mathrm{left} := \bigcap_{j<i}\mathrm{lub}(x_j)$ incrementally:

```
propagate(d):
  right[n] ← U
  for i ← n−1 downto 1:  right[i] ← right[i+1] ∩ lub(d(x[i+1]))
  left ← U
  for i ← 1 to n:
    x[i].adjglb(glb(d(y)) ∩ right[i] ∩ left)
    left ← left ∩ lub(d(x[i]))
```

Each iteration of the second loop is $O(1)$ (one intersection to prune, one intersection to extend `left`), so the whole propagator is $O(n)$ — the same asymptotic win prefix-sums give you over recomputing every subrange sum from scratch. The general recipe: whenever an interval normal form's CNF/DNF contains a subexpression of the shape $\bigcap_{i\ne j}S_i'$ (or dually $\bigcup_{i\ne j}S_i'$) that recurs across multiple variables' normal forms, that's exactly the pattern this technique factors out.

## Implementation: ROBDDs, and compiled beats interpreted

Everything above — ENF, Shannon expansion, CNF/DNF extraction — is symbolic manipulation of Boolean formulas, and Tack doesn't reimplement that machinery from scratch: he represents $S$ as a **Reduced Ordered Binary Decision Diagram (ROBDD)**, Bryant's (1986) canonical representation of a Boolean function $f \in \mathbb B^n \to \mathbb B$ as a DAG where every root-to-leaf path is a variable assignment and the two leaves are the constants $0/1$. "Reduced" (no duplicate subgraphs) plus "ordered" (a fixed global variable order on every path) makes the representation *canonical*: for a fixed variable order, exactly one ROBDD encodes any given $f$.

Existential quantification over ROBDDs is the operation doing the real work: $S[\emptyset/x] = \exists x.\, \overline x \cap S$ and $S[U/x] = \exists x.\, x \cap S$ compute the two halves of $\mathrm{INF}_x$ directly, without ever manipulating a textual formula — and DNF/CNF fall out as paths to the $1$/$0$ leaf, respectively. Given this, the chapter compares two implementation strategies:

- **Interpreted:** build range-iterator objects dynamically from the ROBDD-derived normal forms at run time. Flexible (new propagators can appear without recompiling), but pays for that flexibility with virtual-dispatch iterators (Gecode needs a *second* iterator hierarchy with dynamic binding, since [[Implementing-Views-Efficiently|the template-based iterators]] require compile-time types).
- **Compiled:** emit C++ code — literally generate the source text of a propagator, e.g. for the partition constraint's $y$ lower bound, a chain of `Union`/`Intersection`/`Complement` range-iterator templates composed exactly as the normal form dictates. This is a direct implementation offspring of [[Implementing-Views-Efficiently|Chapter 9's]] monomorphization story: the generated code is parametrically-polymorphic C++, so it compiles to the same zero-overhead machine code a hand-written propagator would.

Table 11.1's benchmarks make the trade-off concrete: interpreted propagators cost anywhere from ~100% to ~1100% of compiled run time across the benchmark suite (Social Golfers: 11.3× slower interpreted; Sudoku: 6–8× slower), with comparable-to-worse memory. The chapter's strongest empirical claim: for the ternary intersection example, the *generated* propagator is literally byte-for-byte what a human would have hand-optimized — meaning a hand-written propagator has essentially no headroom left to beat a compiled one, once common-subexpression elimination and normal-form minimization are applied at compile time.

## Where this leads

Chapter 11 is Part II's second and final answer to "stop hand-writing propagators": [[Views-and-Derived-Propagators|Chapters 7–9]] reuse an *existing* propagator's logic across variants via input/output transformation; this chapter *generates* logic from nothing but an algebraic specification, closing the gap Chapter 10 left open (compiler optimization of view chains has a provable ceiling; specification-to-ROBDD compilation does not hit that ceiling, because it works on the formula's actual structure rather than on a fixed decomposition into iterator adaptors). Both techniques cash out the dissertation's central thesis — that principled derivation beats ad hoc engineering — through genuinely different mechanisms, and Chapter 12's conclusions treat them as the two pillars of Part II. The one loose end the dissertation leaves explicit is **cardinality reasoning** (Section 12.2): none of this chapter's machinery says anything about $|x|$, and cardinality-aware propagation for Boolean set constraints is NP-hard in general (Bessière et al. 2004) — flagged as open.

For the `sat-smt-csp` focus area, this chapter is close to a direct blueprint for a CSP kernel's "compile a declarative constraint spec into a sound-and-complete propagator" front end: the pipeline **grammar → normal form → variable isolation → per-literal bound formula → compiled code**, with a completeness *theorem* (not just an implementation) attached at the normal-form step, is exactly the shape a constraint-generation-and-solving component needs when it has to prove — not just claim — that its propagators are complete with respect to a chosen domain approximation (here, set intervals; in your own kernel, potentially integer intervals, or DFA-shaped domains for structured data). The NP-completeness that surfaces explicitly at two points — DNF/CNF blow-up in Section 11.2, and cardinality reasoning in Section 12.2 — is the same wall every complete constraint-propagation technique eventually hits, and it's worth carrying forward as the standing reminder that "complete propagator" and "tractable propagator" are only the same thing when the domain approximation is chosen carefully enough to keep the underlying decision problem inside a workable complexity class. The ROBDD-as-decision-procedure connection is also a direct SAT-solver analogue worth keeping: existential quantification over an ROBDD is structurally the same case-split a DPLL/CDCL solver performs when branching on a variable, just computed once symbolically instead of repeatedly at search time.
